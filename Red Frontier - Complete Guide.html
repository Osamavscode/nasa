RED FRONTIER — Complete Guide

How the game works, and how to change any part of it. Written for the NASA Space Apps team.
The one rule to remember: you never edit the game you play directly. You edit the source code (the src folder inside RedFrontier-Source.zip), then run one build command, which produces a new playable game. The playable files are compressed and unreadable, so editing them directly does not work.

2. How to play

  1. Main menu → Play → choose Mars Exploration → read the briefing.
  2. Design the rover with the 9 category tabs on the left. The right panel shows live mass, power, mobility and science. Red messages are errors you must fix before continuing (over budget, or over the payload limit).
  3. Plan the route: click the map to add waypoints, or press Auto-plan. Red sections are too steep or too soft for your wheels.
  4. Drive: use WASD, or press R for AutoNav. At each blue beacon, press E and run the science tasks.
  5. Survive up to 3 sols. Nights are skipped automatically, but your battery must last through them.
  6. Read the Results report, improve the design and fly again.

3. The big picture — how it works

The game is a web application written in JavaScript. It uses Three.js for 3D graphics and runs inside a browser window. The Windows .exe version is the same game wrapped in Electron, a small built-in Chrome.

Main menu→Mission select→Briefing→Rover design→Route planning→3D mission→Results

All three core ideas from your vision document are connected through one shared physics file:

  • Engineering design (the Design screen) stores the player's choices in app.state.design, for example { chassis: 'medium', wheels: 'std', solar: 's4', … }.
  • Physics simulation (physics.js) turns those choices into numbers: mass, power, maximum slope, energy use.
  • 3D gameplay (sim.js) calls the same physics functions every frame. That's why choosing narrow wheels really does make you get stuck in the dunes.

The route planner (planner.js) runs the same physics along the planned path to predict battery, time and danger, before you drive.

What happens every frame during the mission (sim.js → step())

  1. Read the keys (or AutoNav steering toward the next waypoint).
  2. Look at the ground under the rover: terrain type and slope in the driving direction.
  3. Traction check: if the slope is too steep or the sand too soft, the speed drops toward 0 and a "wheels slipping" warning appears.
  4. Move the rover, check for boulder collisions and add wheel wear.
  5. Energy: generation (solar + RTG) minus loads (idle + heaters + driving + science + radio) goes into the battery.
  6. Check orbiter relay passes (11:30 and 16:00) and send stored data to Earth.
  7. Check for end conditions: battery 0 → fail; wheels 0 → fail; 17:30 → night (or the end of the mission on sol 3).

4. Set up your PC to edit the game (one time)

  1. Install Node.js LTS from nodejs.org, using all the default options.
  2. Install a code editor. Visual Studio Code (free) is recommended.
  3. Right-click RedFrontier-Source.zip → Extract All. You get a folder RedFrontier-Source.
  4. Open that folder in VS Code (File → Open Folder), then open a terminal (Terminal → New Terminal) and run: 
    npm install --omit=dev
    This downloads the building tools (about 60 MB, one time only). Leave out --omit=dev only if you want to build the .exe (it adds about 120 MB).

The edit → test loop

  1. Edit a file in src/ and save it.
  2. In the terminal, run:
    node build.mjs
  3. Open dist/index.html in Chrome or Edge (double-click it). If it's already open, press F5.
Tip: if something breaks, press F12 in the browser and read the red error in the Console tab. It tells you the file and line. Usually it's a missing comma or quote.
Before big changes, make a copy of the whole RedFrontier-Source folder so you can go back.

6. Texts, team names & credits

  • Team names: src/screens/menu.js → find Team members: add your names here and replace that line, e.g. Team: Eyad, Sara, Omar — Cairo.
  • Data sources list (Credits screen): SOURCES in data.js. Each entry is ['what', 'source'].
  • Briefing text (story, challenges list, environment table): src/screens/missions.js, in the briefing section.
  • Mission cards (Earth / Moon / Mars, difficulty, skills, locked or not): MISSIONS_MENU in data.js.
  • Bottom-corner menu texts: menu.js, the ver and ver2 divs.
  • In-game messages (toasts like "Dust storm arriving"): search for toast( in sim.js.
  • Failure messages: reasonTxt inside the end() function in sim.js.
Text inside the code is between quotes '…' or backticks `…`. If your text contains an apostrophe (for example don't), use backticks or write don\'t.

  • Move a target: change x and z (−420 to +420). x = east (+) / west (−), z = south (+) / north (−). Hover the planning map to read coordinates.
  • Important: targets T1, T2 and T3 also shape the terrain (lakebed, dunes, ridge), because terrain.js reads their positions. Moving them moves those landforms too. T4 sits on the crater rim; if you move it, move CRATER in terrain.js as well.
  • needs: a list of requirements; all must be met. Inside one requirement, | means "or". For example, ['mastcam|navcam'] means either camera works.
    Possible tags: any camera or instrument id, plus scoop, drill, apxs (from the arm).
  • points: science score. dataMb: data size that must be sent to Earth. sample: true: counts as a physical sample.
  • The task id must exist in TASK_INFO (physics.js) and in science.js. To make a new kind of task, see the next section.
  • Adding a 5th target: copy a target block, give it id: 'T5' and a position. It automatically gets a beacon, a map marker, objectives and scoring.

10. Science tasks & results

How long a task takes and how much power it uses: TASK_INFO in physics.js:

export const TASK_INFO = {
  img:  { hours: 0.25, power: 20 },   // 0.25 Mars hours ≈ 15 min, 20 W
  core: { hours: 1.2,  power: 120 },  // drilling: long and power hungry
  …
};

What the player sees as the result: scienceResult() in src/science.js. It has one case per task id. Each one sets instrument, summary (short line), detail (full text) and can change points or dataMb. For example, Navcam-only imaging gets half points.

Rock compositions (SiO₂, FeO… per target): the COMPOSITION table at the top of science.js.

Add a brand-new task type (example: microscope)

  1. In physics.js → TASK_INFO, add micro: { hours: 0.3, power: 10 },
  2. In science.js, add a case before the last } of the switch: 
    case 'micro': {
  instrument = 'MAHLI-type imager';
  summary = 'Grains 0.1–0.5 mm, well rounded';
  detail = 'Close-up images show rounded grains — transported by water.';
  break;
}
  3. In data.js, add the task to a target: { id: 'micro', label: 'Close-up grain images', needs: ['microscope'], dataMb: 15, points: 15 }

12. Terrain & map

src/terrain.js builds the landscape from maths. There are no image files. The height(x, z) function adds these layers:

FeatureSettings objectChange
Rolling hillsfirst line of height()* 9 = hill height; / 220 = hill size
Vera Rubin ridgeRIDGEh height, wid width (smaller = steeper), len, ang rotation
Crater (rim overlook)CRATERx, z, r radius, rim height
Sand dunesDUNES + dune code in height()r field size; prof * 2.4 = dune height (higher = steeper, harder)
Lakebed (flat)LAKEr size
Map edge wallsif (r > 420)keeps the rover inside

Terrain types (sand, rock field, bedrock, gravel) are chosen in terrainType(). Example: if (rockiness(x, z) > 0.3) return 'rocky';. Raise 0.3 to 0.4 for fewer rock fields.

Rocks: rocks(). Up to 1700 rocks; the chance of a rock depends on terrain; big rocks block the rover. Change the seed rng(1234) for a different rock layout.

Different landscape: change the seed numbers in the fbm(…, seed) calls inside height() (for example 3 → 8).

Map colours: COL in mapRender.js. 3D ground colours: color in TERRAIN (data.js).

13. 3D visuals & the rover model

Mars environment (src/world.js)

  • Sky colours: in makeSky(), the zen (top of sky) and hor (horizon) colours as RGB 0–1, e.g. vec3(0.86,0.66,0.48).
  • Fog / haze: scene.fog.density in update().
  • Sun brightness: sun.intensity. Overall brightness: renderer.toneMappingExposure in main.js (1.05).
  • Mount Sharp in the distance: the line with 1400 * Math.exp(…) (1400 = height).
  • Target beacons: the beam colour is 0x3fd0ff; there's a ring around each target. The layered rock at T1 and the hematite pebbles at T3 are built in the same loop.
  • Graphics quality presets (mesh detail, rock count, shadow size): Q at the top of createWorld().

The rover (src/rover.js)

It loads assets/rover.glb (the Curiosity model from your zip) and adds parts based on the design:

  • Wheels are resized and recoloured from the wheel radius, width and color.
  • Solar wings (blue panels) have the correct real area in m².
  • One orange battery box per 600 Wh.
  • A white dish appears for the high-gain antenna and a gold helix for UHF; blue lights for hazcams.
  • The whole rover is scaled by the chassis scale.

Swap the rover model (e.g. your 25042_Perseverance.glb)

  1. Copy the .glb into the source folder, then run: 
    node tools/optimize.mjs "25042_Perseverance.glb" assets/rover.glb
node build.mjs
  2. The game expects the model to be in metres, standing on the ground (y = 0), with its front facing +Z. If it looks too big, too small or rotated, adjust it in buildRover(): model.scale.setScalar(…) and model.rotation.y = Math.PI.
  3. Wheel spinning and resizing look for the mesh named part8 (the wheel part in the Curiosity model). With another model, find its wheel part number. Check the browser console with F12, or simply let the wheels not spin; everything else still works.
Check the licence of any 3D model you use (Sketchfab models often require crediting the author) and add the credit in the Credits screen.

14. Controls & HUD

  • Keys: in sim.js, the this._kd function. Example: change e.code === 'KeyR' to 'KeyF' to move AutoNav to F. Movement keys are in step() (keys.KeyW …). Also update the key list in menu.js (Settings) and in the HUD bottom-right box.
  • Turn speed: S.yaw += steer * 0.55 * … in step().
  • Science range (blue ring): the number 16 (metres) used with nearestTarget().d.
  • Camera: S.cam (distance, angle). The Navcam view is in tick().
  • HUD panels: the HTML at the top of sim's enter() (hud-tl, hud-bl, …). Values are filled in updateHud().
  • Time warp levels: the KeyT handler. Science tasks run at at least ×4 automatically (Math.max(S.warp, 4) in step()).

15. Scoring & results

In evaluate() in src/screens/results.js:

  • Score = science points × data-return factor. Data still onboard at the end counts at 50%.
  • Completion = score ÷ maximum points (200).
  • Status: SUCCESS if completion ≥ 60% and at least 3 targets are done; PARTIAL if ≥ 25%; otherwise FAILED. If the rover died, it's PARTIAL only if ≥ 50%.
  • Grade: S ≥ 90%, A ≥ 75%, B ≥ 55%, C ≥ 35%, otherwise D (×0.85 if the rover was lost).
  • Engineering report ("what helped / what hurt"): each I.push(['good'|'bad'|'tip', 'icon', 'message']). Add your own rule the same way, for example: 
    if (S.odo > 1000) I.push(['good', '🏁', `Long-distance driver: ${S.odo.toFixed(0)} m!`]);

16. Sound

All sounds are made by code in src/audio.js, so there are no files to manage.

  • UI sounds: the sfx object (click, success, fail …). The first number is the pitch in Hz, the second the length in seconds.
  • Menu music: startMusic(), using the notes list (frequencies).
  • Wind and motor: startAmbience() and setAmbience().
  • Use a real music file: put music.mp3 in dist (copy it in build.mjs), then in startMusic() use music = new Audio('music.mp3'); music.loop = true; music.play();, and in stopMusic() use music.pause().

17. Menus, settings & adding screens

  • Every screen is an object with enter(app) (build the page) and optionally exit(). They are listed in src/screens/index.js.
  • To go to a screen from a button, use app.go('design').
  • Add a new screen (e.g. "How to play"): create src/screens/howto.js exporting howto = { enter(app) { … app.html(`<div class="screen">…</div>`) … } }, add it to index.js, and add a button in menu.js: <button class="btn" data-a="howto"> with el.querySelector('[data-a=howto]').onclick = () => app.go('howto');
  • Default settings (quality, volume…): defaults at the top of main.js. Players' choices are saved automatically.
  • Unlock the Moon / Earth cards: set locked: false in MISSIONS_MENU. They currently all lead to the Mars mission, so you'd need a second MISSION to make them different.

18. Build the browser version

node build.mjs          # readable build, good for testing
node build.mjs --min    # smaller build, for sharing

Result: the dist folder (index.html, game.js, rover-model.js, styles.css, fonts). Zip it and share; anyone can double-click index.html. The rover model is embedded inside rover-model.js, which is why it works without a web server.

19. Build the Windows .exe yourself

Building on your own PC avoids downloading the big file. It needs the full install (once): npm install (without --omit=dev). Then, in the terminal (PowerShell) inside RedFrontier-Source:

node build.mjs --min
Remove-Item -Recurse -Force stage -ErrorAction SilentlyContinue
mkdir stage
Copy-Item -Recurse dist stage\game
Copy-Item desktop\main.cjs, desktop\preload.cjs, desktop\icon.png stage\
Copy-Item desktop\app-package.json stage\package.json
node tools\pack.mjs

Result: release\RedFrontier-win32-x64\RedFrontier.exe (keep the whole folder together; the .exe needs the files next to it).

  • Window icon: replace desktop/icon.png (512×512 PNG).
  • Start in fullscreen: in desktop/main.cjs, add fullscreen: true to the BrowserWindow({ … }) options.
  • F11 toggles fullscreen and F12 opens developer tools (for debugging).
  • Windows SmartScreen warns about unsigned apps: More info → Run anyway.
